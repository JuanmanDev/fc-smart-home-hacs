### B. THE decisive remote-unlock test (awake window)
```powershell
python tools\unlock_awake_window.py --wait-mins 15
```
When it says "WAKE THE LOCK NOW":
1. Press the **bell button** on the lock (fastest way to wake it).
2. Watch the script: it fires openLock within 1-2s of the event.
3. Outcomes:
   - **Door opens** → theory confirmed → I implement auto-retry logic
     in the HA lock entity (wake+retry) and we test from HA UI.
   - **682 even while awake** → theory wrong → we diff against the
     official app (see C).
   - **No event at all** → lock WiFi is disconnected from cloud
     (check lock WiFi LED / app device page "online" state).

### C. If B fails: capture the official app doing a remote unlock
Run mitmproxy capture on the phone while doing a remote unlock from the
OFFICIAL app (if it works). The difference between our request and the
app's will be in: extra header, extra body field, or a preceding call we
missed. (All capture tooling from 2026-09-08 is in
`%TEMP%\opencode\mitm\`.)
